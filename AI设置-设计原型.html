05实现要点

  • 请求层只写一份。全部走 POST {base_url}/chat/completions，请求体是 OpenAI 标准结构。不做「智谱一套、OpenAI 一套」的分支。
  • HTTP 用 WinHTTP。系统自带，不必为发 HTTPS 再引第三方库，和「零依赖」原则一致。要处理超时与代理。
  • API Key 不进日志、不进崩溃 dump。出错只记状态码和服务商名，不记请求头。
  • 发送前做字段白名单过滤。只挑时段分布、占比、Top 榜这类聚合值进 prompt；文件路径、歌词一律挡在本地 —— 这是用户故事里承诺过的。
  • 网络请求不能卡界面。放工作线程，结果 PostMessage 回主线程（同 WM_STAT_RECORD_APPENDED 的路子）。
  • 多语言键先加 English.ini。工程把 English.ini 内嵌进 exe 兜底，新键漏了它其它语言会显示成键名。
  • 页签图标。若 IconMgr 没有合适的，用现有的 IT_Online，或按需加一个 IT_Ai 图标资源。
  • 「获取可用模型」走标准接口：GET {base_url}/models， 请求头 Authorization: Bearer <key>，返回 {"data":[{"id":"..."}]}， 把这些 id 填进模型名下拉即可。失败时（401 / 连不上 / 服务商压根没实现这个端点）要能 优雅退回手填 —— 不能把「拿不到列表」变成「不能保存配置」。
  • 参考 dsh（DeepSeek Harness）的配置形态（你的 ~/.dsh/settings.yaml）： 每个 provider 都标 api: openai-completions + baseURL + models: [{id, name}]，key 走环境变量。 「全走 OpenAI 兼容格式」这条跟我们完全一致；差别只在于我们按桌面软件的惯例 把 key 存进设置文件（而非环境变量），并把模型列表做成可拉取的。
