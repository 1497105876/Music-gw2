## 0. 一句话定义

新增一个与原生「累计播放时间统计」页面**并存**的独立统计页面：**「播放日志统计」**。
它只读取逐次播放日志（下称 **playlog**），提供 **6 个原生 Tab 页（纯列表与数值，零自绘图表）**，并通过页面内的 **「生成网页报告」按钮** 把所有图形化分析交付给本地 HTML 报告。

## 2. 用户故事（本次定稿版）

> 六个 US 全部来自已确认的需求侧故事集合，并按本次范围裁剪。**US-7 不在本期范围**（见 §3.3）。

**US-1 日常回看（普通听众）**
作为每天听歌的用户，我想一打开页面就看到**默认近 30 天**的播放时长、播放次数、完播率、活跃天数，以便 3 秒内知道最近听得怎么样。
- 验收锚点：`AC-1`

**US-2 排行与口味（普通听众）**
作为想知道自己口味的用户，我想看到**最常听的歌手 / 专辑 / 曲目**榜单（按时长或次数降序），以便知道自己反复在听什么。
- 验收锚点：`AC-4`

**US-3 时间探索（爱折腾数据的人）**
作为想对比不同时期的用户，我想**自定义起止日期**，让概览、趋势、榜单全部按该区间重算，并能在**日 / 周 / 月 / 年**四个尺度上查看趋势，以便对比"去年 12 月"和"今年上半年"。
- 验收锚点：`AC-2`、`AC-3`、`AC-5`

**US-4 图形化分析与分享（想看图表的人）**
作为不想读表格的用户，我想点一下按钮就得到一份**包含全部图表的网页报告**（本地单文件、不发网络请求），以便直观查看趋势、时段、热力分布并分享。
- 验收锚点：`AC-6`、`AC-7`

**US-5 明细核查（爱折腾数据的人）**
作为想查单条记录的用户，我想看到**不经任何过滤的原始播放流水**（含被口径排除的短播放），以便核对某个数字是怎么来的。
- 验收锚点：`AC-8`

**US-6 口径可信（所有人）**
作为看到数字会怀疑的用户，我想点一个「?」就知道**哪些记录被计入、时长怎么算、数据存在哪**，以便信任这些数字。
- 验收锚点：`AC-9`

**US-7 走势对比（爱折腾数据的人）**
作为关心涨跌的用户，我想看到**环比（上一个等长周期）与同比（去年同期）**的差值，以便知道自己是听得多了还是少了。
- 验收锚点：`AC-10`
- 说明：本条在早期取舍中被降优先级，本次在「趋势」页以摘要形式恢复，理由见 §3.5 交叉复核 C-3。

## 3. 功能取舍总表（保留 / 废弃 / 新增）

### 3.1 【保留】—— 本次不动的既有资产

| # | 对象 | 层级 | 保留理由 |
|---|---|---|---|
| K-1 | 「累计播放时间统计」页面与其菜单入口 | UI | 本次是**并存**新页面，不是替换；两个入口对应两套口径（媒体库累计值 vs 逐次日志） |
| K-2 | playlog 采集与按月落盘模块 | 数据层 | 唯一数据源；本次不做任何采集侧改动 |
| K-3 | playlog 文件本体与既有历史数据 | 数据 | 不迁移、不改写、不清理；历史起点之前的空区间如实显示"无记录" |
| K-4 | 纯聚合计算能力（与界面无关的一组计算函数） | 聚合层 | 与新页面所需指标高度重合；**口径必须与之保持一致** |
| K-5 | 统计公共类型（过滤结构、聚合结果结构、变更通知消息） | 公共层 | 契约一致，避免重复定义两套结构体 |
| K-6 | 网页报告的生成与打开通路 | 报告层 | 本次只把入口迁移到新页面，生成能力继续用 |
| K-7 | 后台刷新机制（写入后通知 + 打开期间周期性重算） | 运行时 | 满足近实时，不需要新发明 |
| K-8 | 口径变更记录文件 | 数据 | 供「?」说明读取展示 |

> 边界纪律：**K-4 / K-5 / K-6 只允许调用，不允许照抄其内部结构**。某个指标若缺失 → 在 K-4 上新增，**禁止在新页面内就地重算一遍**（这是此前两套口径漂移的根因）。

### 3.2 【废弃】—— 本次删除的既有入口

| # | 对象 | 处理方式 | 理由 |
|---|---|---|---|
| F-1 | 网页报告的**独立菜单入口**（单独菜单命令） | 从菜单与命令处理中整体移除 | 用户明确：报告按钮并入新页面；同一功能两个入口会造成"报告该从哪进"的困惑 |
| F-2 | 该入口"自加载全量后出报告"的调用方式 | 不保留无筛选的报告入口 | 报告必须跟随页面当前区间，否则出现"页面近 30 天、报告是全量"的口径割裂 |
| F-3 | 原生统计页里的自绘图表区域与占位控件 | 不重建 | 决策 `D-4`：原生零图表，图形全部交给网页报告 |
| F-4 | 「数据更新至 HH:MM」时间标注 | 不引入 | 项目内无状态栏/时间戳先例，单独出现显得外来（沿用既有决策） |
| F-5 | 全局粒度切换按钮组（天/周/月/年） | 不作为全局控件 | 之前因"趋势图上无可见效果"被移除；本次改为**趋势页局部控件**（`N-9`） |

### 3.5 取舍交叉复核（为什么这样切）

| # | 复核点 | 结论 |
|---|---|---|
| C-1 | 已有"老统计页"，为何不直接改它？ | 用户选定并存（决策 `D-1`）。两者口径不同源，合并会逼出一堆"以谁为准"的问题；并存让老口径用户不受影响，也让本次可以零包袱重写 |
| C-2 | 既然要并存，为何又删掉报告菜单入口？ | 报告的数据源是 playlog，**与新页面同源**；入口留在新页面内才能保证"筛选一致"。挂在全局菜单反而制造割裂（`F-2`） |
| C-3 | 为什么删了列导出按钮？ | 报告里已含明细表；再做一个 CSV 按钮等于两套导出维护。**若用户坚持要 CSV，建议加在"明细"页而非底部按钮行**（待确认 `Q-3`） |
| C-4 | 为何恢复"粒度切换"（此前被删）？ | 被删的原因是"趋势图占位后无可见效果"。本次趋势是**表格**，粒度切换有明确的可见效果（分组行会变），因此以局部控件形式恢复，不再影响其它页（`F-5` / `N-9`） |
| C-5 | 为何保留周期对比（US-7）？ | 它不依赖任何图表，纯数字即可表达，且在趋势页以两行摘要呈现成本极低；此前搁置是因为那时它挂在图上 |

### 4.3 Tab 容器

- 控件：`CTabCtrlEx`（自带子窗口管理、`OnSize` → 子页跟随缩放）。
- 6 个页签，标题 ≤3 字：**概览 / 趋势 / 歌手 / 专辑 / 曲目 / 明细**。
- 子页均为 `CTabDlg` 派生：`GetDialogName()` 返回空、`IsRememberDialogSizeEnable()` 返回 false。
- 切换路径：`SetCurTab()` → 子页 `OnTabEntered()`（脏标记决定是否重算）→ 焦点交给本页主列表控件。
- **过滤状态由主对话框持有**，切 Tab 不丢失、不重新读文件。

### 4.9 资源费注意事项（.rc 写法）

- `.rc` 文件为 **UTF-16LE + BOM + CRLF**，只能按字节读取 → 精确替换 → 写回。
- 字体规范：`FONT 9, "微软雅黑", 400, 0, 0x0`。
- **每个新增对话框必须同时有「定义段」与 `AFX_DIALOG_LAYOUT` 段**，成对出现，否则运行时布局失效。

### 4.10 布局规则表（AFX_DIALOG_LAYOUT）

## 6. 统计指标定义与计算口径

### 6.1 唯一口径收口

```
IsCounted(record)  :=  record.play_duration_sec >= 15
```

| 规则 | 说明 |
|---|---|
| R-1 | **除「明细」页外，所有指标、榜单、时间桶、周期对比，一律只处理 `IsCounted()==true` 的记录** |
| R-2 | 「明细」页展示全部记录（含不满足条件的），但第 9 列必须标"否" |
| R-3 | 过滤顺序：**先按时间区间过滤 → 再按 IsCounted 过滤 → 再聚合**。区间过滤只允许做一次，子页禁止二次按日期过滤 |
| R-4 | 时间分区一律用**整数键**：日期键 `YYYYMMDD`、小时取 `[0,23]`、月键 `YYYYMM`、年键 `YYYY` |
| R-5 | `song_length_sec` 单位为**毫秒**，参与"曲目总长/完成度"计算前必须 `/1000`；`play_duration_sec` 单位为秒 |
| R-6 | 除数为 0 时一律返回"—"（不返回 0、不返回 NaN），此规则对所有比率/均值生效 |
| R-7 | 所有比值以 **1 位小数 + %** 展示；时长按 §6.5 格式化 |

### 6.2 概览页指标全表

> 「组」用于列表分组标题；「键」为语言键；所有"时长"字段单位在内存中统一为秒。

#### 组 A · 基本统计

| # | 指标 | 语言键 | 计算口径 | 边界 |
|---|---|---|---|---|
| A1 | 总播放时长 | `TXT_PLAYLOG_M_TOTAL_DUR` | 区间内有效记录 `play_duration_sec` 求和 | 无记录 → `0秒`（不是"—"，此为唯一例外，见 D-1） |
| A2 | 播放次数 | `TXT_PLAYLOG_M_TOTAL_CNT` | 区间内有效记录条数 | 同上 |
| A3 | 涉及曲目数 | `TXT_PLAYLOG_M_SONG_CNT` | 去重 `file_path` 计数 | 去重按**路径字符串精确匹配**，不做大小写折叠 |
| A4 | 活跃天数 | `TXT_PLAYLOG_M_ACTIVE_DAYS` | 去重日期键计数 | |
| A5 | 日均时长 | `TXT_PLAYLOG_M_AVG_DUR` | A1 / A4 | A4=0 → "—" |
| A6 | 日均次数 | `TXT_PLAYLOG_M_AVG_CNT` | A2 / A4 | A4=0 → "—" |
| A7 | 数据起始日 | `TXT_PLAYLOG_M_FIRSTDAY` | 全量数据中最早记录日期键 | 无数据 → "—" |

> **决策 D-1**：A1/A2 在无数据时显示 `0`（"这段时间没听歌"是真实且有用的信息），其余所有衍生指标显示 `—`。此例外必须写进口径说明。

#### 组 B · 播放行为

| # | 指标 | 语言键 | 计算口径 | 边界 |
|---|---|---|---|---|
| B1 | 播完次数 / 播完率 | `TXT_PLAYLOG_M_COMPLETED` | 结束状态 = 播完 的记录数 / A2 | A2=0 → "—" |
| B2 | 跳过次数 / 跳过率 | `TXT_PLAYLOG_M_SKIPPED` | 同上，状态 = 跳过 | 同上 |
| B3 | 停止次数 / 停止率 | `TXT_PLAYLOG_M_STOPPED` | 同上，状态 = 停止 | 同上 |
| B4 | 出错次数 / 出错率 | `TXT_PLAYLOG_M_ERROR` | 同上，状态 = 出错 | 同上 |
| B5 | 平均单次时长 | `TXT_PLAYLOG_M_AVG_ONCE` | A1 / A2 | A2=0 → "—" |
| B6 | 平均完成度 | `TXT_PLAYLOG_M_AVG_COMPLETION` | 对每条有效记录算 `min(1, play_duration_sec / (song_length_sec/1000))`，取算术平均 | `song_length_sec <= 0` 的记录**排除出分母**；全排除 → "—" |
| B7 | 平均跳过位置 | `TXT_PLAYLOG_M_AVG_SKIP_POS` | 仅取状态 = 跳过的有效记录，算 B6 同式 | 无跳过记录 → "—" |

展示约定：B1~B4 一行两值，格式 `次数（百分比%）`。

#### 组 C · 听歌习惯

| # | 指标 | 语言键 | 计算口径 | 边界 |
|---|---|---|---|---|
| C1 | 最活跃时段 | `TXT_PLAYLOG_M_PEAK_HOUR` | 24 个整点桶中**有效记录条数**最大的桶 | 并列时取**小时数较小者**；无数据 → "—" |

| C4 | 当前连续天数 | `TXT_PLAYLOG_M_STREAK` | 从**今天**（无则区间结束日）向前回溯，活跃日连续计数 | 今天/区间结束日不活跃 → `0` |

### 6.3 趋势页时间桶

| 粒度 | 桶键 | 展示标签格式 | 补齐规则 |
|---|---|---|---|
| 日 | `YYYYMMDD` | `MM-DD`（跨年时 `YYYY-MM-DD`） | 桶数 ≤ 400 时补齐连续日；> 400 时只列有记录的桶，并在对比文本首行标注 `TXT_PLAYLOG_TREND_PARTIAL` |
| 周 | 该周**周一**日期键 | `MM-DD 周` + 起止提示见下 | 补齐连续周；周起始日固定为**周一** |
| 月 | `YYYYMM` | `YYYY-MM` | 补齐连续月 |
| 年 | `YYYY` | `YYYY` | 补齐连续年 |

每行四列：

| 列 | 口径 |
|---|---|
| 时间桶 | 按上表标签 |
| 播放次数 | 桶内有效记录条数（可为 `0`） |
| 播放时长 | 桶内有效记录 `play_duration_sec` 求和（可为 `0秒`） |
| 占区间时长比 | 该桶时长 / 区间总时长 A1，1 位小数 `%`；A1=0 → `—`（不画假装数据的零柱） |

排序：按桶键**升序**（时间从早到晚）。

### 6.4 周期对比（US-7）

在趋势页底部以两行只读文本呈现：

| 行 | 口径 |
|---|---|
| 环比 | 上一个**等长**周期：长度 `L = 结束日 - 起始日 + 1` 天；上一期 = `[起始日 - L, 起始日 - 1]`。对比**播放次数**与**播放时长**，输出 `变化量` 与 `变化率%`。上一期完全无记录 → 显示 `TXT_PLAYLOG_COMPARE_NO_DATA`（不显示 `+∞%`） |
| 同比 | 去年同期：把起始日、结束日各自减 1 年（2 月 29 日 → 2 月 28 日）。同一套输出规则 |

- 格式：`上一期：N 次 / X 小时Y 分（较本期 +a 次，+b%）`
- 变化率计算：基期为 0 时输出 `TXT_PLAYLOG_COMPARE_NA`（"—"），**不允许出现 Infinity**。
- 「去年同期」的算式过程必须在聚合层完成，界面层只负责拼字符串（见 §11.2 分层纪律）。

### 6.5 格式化规则

| 类型 | 规则 | 示例 |
|---|---|---|
| 时长 < 1 小时 | `M 分 S 秒` | `8 分 5 秒` |
| 时长 ≥ 1 小时 | `H 小时 M 分 S 秒` | `12 小时 5 分 3 秒` |
| 时长为 0 | `0 秒` | |
| 百分比 | 1 位小数 + `%` | `63.2%` |
| 日期 | 与语言环境一致的短日期，统一走语言/系统格式 | |
| 未知值 | `—`（U+2014） | |

时区：**一律按本机本地时区**，日期与小时直接从记录时间字段截取，不做 UTC 换算（R-6 / 口径说明第 6 条）。

## 7. 时间维度与筛选条件

### 7.1 过滤的责任划分

```
主对话框持有唯一过滤状态：
    StatFilter { from_ymd, to_ymd }        // 0 表示无界
        ↓ ApplyFilter() —— 唯一过滤点
    m_filtered_records（已按区间切好）
        ↓ BroadcastContext()
    6 个子页 —— 只读 + 聚合，禁止二次过滤
```

- 子页**禁止**自行按日期筛选，也禁止缓存一份自己的过滤结果。
- 趋势页的粒度切换**不是过滤**，它只改变分组方式，输入仍是 `m_filtered_records`。

### 7.2 范围预设档位（下拉，7 项）

| 序 | 语言键 | 中文档位 | `from_ymd` | `to_ymd` |
|---|---|---|---|---|
| 0 | `TXT_PLAYLOG_RANGE_7D` | 近 7 天 | 今天 - 6 | 今天 |
| 1 | `TXT_PLAYLOG_RANGE_30D` | 近 30 天（**默认**） | 今天 - 29 | 今天 |
| 2 | `TXT_PLAYLOG_RANGE_90D` | 近 90 天 | 今天 - 89 | 今天 |
| 3 | `TXT_PLAYLOG_RANGE_THISYEAR` | 今年 | 本年 1 月 1 日 | 今天 |
| 4 | `TXT_PLAYLOG_RANGE_LASTYEAR` | 去年 | 去年 1 月 1 日 | 去年 12 月 31 日 |
| 5 | `TXT_PLAYLOG_RANGE_ALL` | 全部 | 0（无界） | 0（无界） |
| 6 | `TXT_PLAYLOG_RANGE_CUSTOM` | 自定义 | 用户指定 | 用户指定 |

- 下拉项顺序与枚举顺序一一对应，**不得**按显示文本排序。
- 「自定义」这一项**不在下拉里被用户主动选中时出现**：它由用户改动日期控件后自动置位（见 §7.5），下拉选择来展现"当前是自定义"。

### 7.3 日期控件的状态规则

| 场景 | 起始 / 结束控件值 | 是否启用 |
|---|---|---|
| 非「全部」预设 | 按 7.2 计算出的区间 | 启用 |
| 「全部」预设 | 数据实际最早日 / 最晚日（无数据则显示今天） | **禁用**（灰显） |
| 用户改动日期 | 用户输入 | 启用，预设自动切到「自定义」 |

### 7.4 粒度（仅趋势页）

- 控件：下拉 `IDC_PLAYLOG_TREND_GRAIN`，4 项，语言键 `TXT_PLAYLOG_GRAIN_DAY/WEEK/MONTH/YEAR`。
- 默认：**日**。
- 影响范围：**仅趋势页的表格分组** + 报告中的趋势数据（报告与页面保持同一粒度）。
- 不影响：概览指标、三个榜单、明细页。
- 切换后立刻重算本页，并标记报告数据为脏。

### 7.5 交互时序与校验

| 触发 | 行为 |
|---|---|
| 下拉选中某项 | 立即重算区间 → 刷新 → 刷新日期控件显示 |
| 日期控件改动 | **300ms 防抖**后应用；控件失去焦点时立即应用（防抖定时器取消） |
| 应用时的校验 | `from <= to` 成立才应用；不成立 → **拒绝应用**，回滚到改动前的值，弹一次提示（`MSG_PLAYLOG_DATE_INVALID`），**不允许产出空结果集** |
| 「?」按钮 | 弹 §5 的说明对话框 |
| 「刷新」按钮 | 重读 playlog 并全量重算（同 §8.3 手动路径） |

### 7.6 空边界区间

- 用户选了区间但区间内 0 条记录 → 各页进入**空态**（§10.2），不报错、不崩溃。
- 「全部」且数据为空时，日期控件显示今天并禁用。
- 「今年」在 1 月 1 日打开时区间为 `[今年1月1日, 今天]`（同一天，长度 1 天），合法，不报错。

## 8. 数据来源与更新频率

### 8.1 数据源

| 项 | 规格 |
|---|---|
| 唯一数据源 | `statistics/playlog_YYYY-MM.jsonl`（按月一个文件），位于用户数据目录下的 `statistics\` 子目录 |
| 是否写入 | **只读**。本页不写任何数据（除网页报告的临时产出文件） |
| 需要的字段 | 文件路径、播放时间、标题、艺术家、专辑、本次播放时长、曲目总长、结束状态、来源 |
| 不需要的字段 | 音量、随机标记、比特率、采样率、声道数、流派 —— 本期不展示、不聚合 |

### 8.2 加载时机

| 时机 | 行为 |
|---|---|
| 对话框构造后 / 首次展示前 | **一次性**扫描并加载全部月份文件 → 内存记录表 |
| 打开期间 | 不再重复全量加载；所有重算是内存计算 |
| 收到"新记录已追加"通知 | 标记脏 → 延迟 200ms 合并刷新（防止一首接一首切歌时抖动） |
| 60 秒兜底定时器 | 重读**当月**文件的新增行 + 全量重算（不落盘缓存） |
| 用户点「刷新」 | 立即执行同上流程 |

### 8.3 刷新流水线

```
重读当月文件（只读新增部分）
   → 合并进内存记录表
   → 重新执行 区间过滤 + IsCounted 过滤   （唯一收口，§6.1 R-3）
   → 重算各指标/榜单/时间桶     （全部在聚合层，禁止页面内手算）
   → 广播给已加载子页 → 当前子页重绘，其余标记脏，进入时再刷
```

### 8.4 错误处理与降级

| 异常 | 处理 | 用户可见表现 |
|---|---|---|
| `statistics` 目录不存在 | 视为"无数据"，不报错 | 全部页空态 + 报告按钮禁用 |
| 目录下无任何 jsonl 文件 | 同上 | 同上 |
| 某行格式损坏/字段缺失 | **跳过该行并计数**，继续解析其它行 | 底部警示行显示 `TXT_PLAYLOG_WARN_SKIPPED`（N=条数） |
| 某文件读取失败（被占用/权限） | 重试 1 次（间隔 200ms）；仍失败 → 跳过该文件，计数 | 同上，文案用 `TXT_PLAYLOG_WARN_FILE_FAILED`（M=文件数） |
| 全部文件均读取失败 | 进入"数据不可用"状态 | 全部页显示 `TXT_PLAYLOG_ERR_LOAD`，报告按钮禁用，**保留关闭按钮可用** |
| 记录时间字段无法解析 | 跳过该行，计入损坏计数 | 同上 |
| 数值字段为负或异常大 | 视为字段异常：该条记录**整条跳过**并计入损坏计数 | 同上 |

> 纪律：**任何解析异常都不允许抛到 UI、不允许弹窗、不允许中断加载**；一律降级为"跳过 + 计数 + 底部一行提示"。

### 8.5 性能约束

| 约束 | 目标 |
|---|---|
| 首次打开到首屏可见 | ≤ 1 秒（2 万条量级下；实测同类解析为毫秒级，留足余量） |

| 切换区间/粒度 | ≤ 300ms |

## 9. 网页报告子规范（US-4）

### 9.1 入口与位置

- 入口：**只在新统计页面的 `IDC_PLAYLOG_BTN_REPORT` 按钮**，替代被删的独立菜单入口（`F-1`）。
- 报告必须携带**当前用户的过滤状态**：时间区间 + 趋势粒度 + 全部已算好的聚合结果。

### 9.2 数据契约（页面 → 报告）

报告输入**必须**是"已经算好的值"，不允许报告层重新遍历原始记录做二次计算，否则页面与报告会口径漂移。至少包含：

| 组 | 键 |
|---|---|
| 区间描述 | 起始日、结束日、所选预设名、生成时刻 |
| 概览 | §6.2 的 A1~A7、B1~B7、C1~C8、D1~D4 全部同名指标 |
| 趋势 | 时间桶数组 `{label, count, duration_sec, percent}` + 当前粒度 |
| 对比 | 环比/同比的 `{是否存在基期, 基期标签, 基期次数, 差值, 变化率或 null}` |
| 榜单 | 歌手 / 专辑 / 曲目 Top 20（含名称、时长、次数、涉及曲目数 / 最后播放） |
| 24 小时分布 | 24 个整点的次数数组 |
| 跳过位置分布 | 4 个桶（0-25 / 25-50 / 50-75 / 75-100%）的次数与占比，仅统计"跳过"记录 |
| 来源贡献 | Top 5 来源 `{名称, 次数, 时长, 占比}` |
| 明细（可选） | 最近 N 条（默认 500），**不含本地文件绝对路径**（隐私） |
| 口径 | 口径版本号 + 最近一条变更记录 |

> 隐私约束：**报告是本地文件，但可能被随手转发** → 明细数据不得包含本地磁盘绝对路径。

### 9.3 产出与打开

| 项 | 规格 |
|---|---|
| 输出目录 | 系统临时目录 |
| 文件名 | `播放日志统计_{起始日}_{结束日}.html`（日期段为实际生效区间；无界时用数据实际边界） |
| 编码 | UTF-8 **带 BOM**（否则中文乱码） |
| 打开 | 系统默认浏览器；打开失败时提示 `MSG_PLAYLOG_OPEN_FAILED`，不重试、不崩溃 |
| 重复生成 | 覆盖同名文件，不做版本号追加 |

### 9.4 HTML 兼容性与观感要求（"最好看 + 兼容性最强"）

硬约束（缺一不可）：

1. **单文件**：所有 CSS/JS 内联，**零外部资源**（不引 CDN、不引在线字体、不发任何网络请求）。
2. **零第三方库**：不引图表库；图形一律用**内联 SVG 或纯 CSS 条形/网格**实现。
3. **保守 JS 语法**：不使用实验特性；基础 DOM API 为主。
4. **布局**：优先 flex + grid，并在不支持时仍能线性排布（流式降级）。
5. **深色/浅色**：用 `prefers-color-scheme` 双套变量，跟随系统。
6. **打印**：`@media print` 下取消粘性导航、展开全部区块、隐藏交互提示。
7. **响应式**：至少两档断点（宽屏多列 / 窄屏单列堆叠）。
8. **锚点导航**：顶部粘性导航 + 高亮当前区块（随滚动更新）。
9. **空数据呈现**：区块内明确显示"该区间内无记录"，**不允许画空图表或假数据**。
10. **零遥测**：不加载任何外域资源，不做任何统计上报。

报告建议区块（编号与页面 Tab 对应，便于交叉核对）：

| 区 | 内容 | 对应页面 |
|---|---|---|
| 01 | 关键指标卡 | 概览组 A |
| 02 | 播放趋势 + 环比同比 | 趋势页 |
| 03 | 24 小时分布 | 概览 C1 / C2 |
| 04 | 每日热力网格 | 趋势「日」粒度的数据换一种视觉表达 |
| 05 | 榜单（歌手 / 专辑 / 曲目） | 三个排行页 |

## 10. 边界场景、交互状态与展示状态

### 10.1 状态机

```
[加载中] ──成功(有数据)──> [正常]
    │                        │
    ├─成功(无数据)──────> [空态]
    └─全失败────────────> [错误态]

[正常] ──改区间到无结果──> [空态]
[空态] ──改区间到有结果──> [正常]
[正常/空态] ──数据加载失败──> [错误态]
[错误态] ──点刷新成功─────> [正常] 或 [空态]
```

### 10.2 空态（无符合条件的数据）

| 位置 | 表现 |
|---|---|
| 概览 | 列表仍显示全部指标项；A1/A2 = `0`，其余 = `—`（见 D-1）。**不允许留空列表** |
| 趋势 | 列表空 + 一行 `TXT_PLAYLOG_EMPTY_TREND` |
| 三个排行页 | 列表空 + 一行 `TXT_PLAYLOG_EMPTY_RANK` |
| 明细 | 列表空 + 一行 `TXT_PLAYLOG_EMPTY_DETAIL` |
| 对比文本 | 两行均显示 `TXT_PLAYLOG_COMPARE_NO_DATA` |
| 「生成网页报告」 | **禁用**（见 §10.5 启用规则） |
| 「刷新」 | 保持可用 |

### 10.3 加载态

- 首次加载**预期为毫秒级**，因此**不引入进度条/loading 遮罩**（避免新增视觉噪音）。
- 若实测 > 300ms：在 Tab 区上方显示一行文本 `TXT_PLAYLOG_LOADING`，完成后移除。此分支默认关闭，需实测触发才启用。
- 刷新耗时期间，保持界面可操作，不阻塞消息泵。

### 10.4 错误态

| 场景 | 表现 |
|---|---|
| 数据完全读不到 | 所有 Tab 显示 `TXT_PLAYLOG_ERR_LOAD`；报告按钮禁用；刷新按钮保持可用 |
| 部分文件失败 | 正常渲染（用读到的部分）+ 底部警示行 `TXT_PLAYLOG_WARN_FILE_FAILED` |
| 有损坏行 | 正常渲染 + 底部警示行 `TXT_PLAYLOG_WARN_SKIPPED` |
| 报告生成失败 | 提示 `MSG_PLAYLOG_REPORT_FAILED`，页面保持不变 |
| 报告打开失败 | 提示 `MSG_PLAYLOG_OPEN_FAILED`，报告文件已生成则不删除 |

### 10.5 控件可用性矩阵

| 控件 | 正常 | 空态 | 错误态 |
|---|---|---|---|
| 范围预设下拉 | ✔ | ✔ | ✔ |

| # | 规则 |
|---|---|

## 12. 验收标准（AC）

> 每条 AC 都绑定 US 与功能编号，可作为实现完成后的逐条勾选清单。

**AC-1 默认近 30 天四指标（US-1）**
- [ ] 打开页面，范围预设默认停在「近 30 天」。
- [ ] 概览页首屏可见：总播放时长、播放次数、完播率、活跃天数，且数值与趋势页、榜单页在同一区间下完全同源。
- [ ] 无数据时：总时长/次数显示 `0`，其余显示 `—`；不出现 `NaN`、`Infinity`、空白行。
