## 1. 产品目标

把"播放统计"从**一个只能看现状的静态报表**，提升为**一个可自由探查、可解释、可分享、可追问的个人听歌数据中心**：用户能在同一页面上任意圈定时间范围与聚合粒度，让所有图表同步联动重绘；能从图表下钻到具体歌手/专辑/歌曲，再一键跳回媒体库继续播放；能看到由本地规则引擎实时生成的"音乐 DNA / 口味漂移 / 异常归因"等自然语言解读，并可选地接入用户自配的 OpenAI 兼容端点把解读升级为对话式问答；所有能力均保持**纯本地、零强制依赖、无遥测**，且在约 1~2 万条（3 年）历史数据下首屏渲染仍 ≤1s。

一句话：**从"能看"到"能查、能钻、能懂、能分享"。**

## 2. 用户故事

> 角色：`Listener`（普通听众）／`Analyst`（爱折腾数据的人）／`Sharer`（想分享的人）。

**US-1 日常回看（Listener）**
作为一位每天听歌的普通用户，我想要一打开统计页就看到"近 30 天的时长/次数/完播率/活跃天数"四张指标卡，以便 3 秒内知道我最近听得怎么样。
- 验收点：默认时间范围为近 30 天；四张卡片数值与切换粒度后的口径一致；无记录时显示"—"而非 0。

**US-2 口味洞察（Listener）**
作为想知道自己口味的人，我想要看到"最常听的专辑/流派占比、音乐 DNA 标签、口味漂移"等可视化，以便理解自己的听歌偏好。
- 验收点：专辑榜、流派环形图、DNA 报告均可点开；数据为空时给明确提示（如 FLAC 常无 genre）。

**US-3 时间范围探索（Analyst）**
作为爱折腾数据的人，我想要自定义起止日期并切换天/周/月/年粒度，让所有图表同步重绘，以便对比"去年 12 月"和"今年上半年"的差异。
- 验收点：改日期或粒度后，指标卡、趋势图、榜单、AI 洞察**全部同步**按新口径重算；切换粒度后 X 轴标签与聚合口径同步变化。

**US-4 报告分享（Sharer）**
作为想分享的人，我想要一键生成年度/月度报告并导出为图片海报（可选带昵称水印），以便发到社交平台。
- 验收点：海报由 GDI 绘制后导出 PNG；默认无水印，昵称水印为设置项可开关；导出文件不带任何网络上传。

**US-5 AI 问答（Analyst）**
作为想问数据的人，我想要用自然语言提问（如"上个月听得最多的歌手是谁"），由本地规则引擎先解析固定问法、可选接入自配模型兜底，以便不必自己翻图表。
- 验收点：不配置任何模型时，固定问法（时间+维度+排序）仍能本地回答；配置端点后复杂问法可用；发送给外部模型的**仅聚合统计值**，`file_path`/歌名明细不出本机。

## 3. 主流程验收标准（7 条）

> 第 1~6 条采用《用户故事-整理版》第二节判定结论；第 7 条按文档建议**改写**为"窗口缩放自适应 + 图表超宽横向滚动"。

**AC-1 默认近 30 天总览四指标卡**（✅ 直接可实现）
- [ ] 打开统计页默认时间范围为近 30 天，概览页顶部以卡片形式展示：总时长、播放次数、完播率、活跃天数。
- [ ] 四张卡片数值与"趋势/排行"等页在相同时间范围下同源、同口径（均过滤 `play_duration_sec < 15`）。
- [ ] 无数据时显示"—"，不显示 0 或 NaN。
- [ ] 卡片数值随全局时间范围/粒度变化实时刷新。

**AC-2 天/周/月/年粒度切换，图表重绘**（✅ 直接可实现）
- [ ] 提供天/周/月/年四档粒度切换控件，默认"天"。
- [ ] 切换粒度后，趋势图 X 轴标签格式与聚合口径**同步**变化（天→`MM-DD`、周→`Www`/周起始日、月→`YYYY-MM`、年→`YYYY`）。
- [ ] 切换粒度后，指标卡与榜单按新粒度重算（如"周"粒度下日均/次数按周聚合）。
- [ ] 切换无闪烁，连续切换 10 次不丢帧、不崩溃。

**AC-3 自定义时间范围（如 2025-01-01 至 2025-06-30）**（✅ 直接可实现）
- [ ] 提供起、止两个日期选择控件，可选任意区间。
- [ ] 选定区间后，所有统计页（含 AI 洞察）按该区间重算。
- [ ] 起日期晚于止日期时给出提示并拒绝应用，不产生空图。
- [ ] 时间范围跨越无数据月份时，如实标注"无记录"，不绘制假数据（参考 §4 风险 R1）。

**AC-4 歌曲 Top10 点击跳转歌曲页**（🔧 需接现有体系）
- [ ] 歌曲排行 Top10 条目可点击，定位到媒体库"歌曲"分类页对应曲目。
- [ ] 通过 `file_path` 精确定位；找不到该文件时给"文件不存在"提示，不崩溃。
- [ ] 跳转后原统计对话框可正常返回（模态/非模态行为明确）。

**AC-5 歌手 Top10 点击跳转歌手页**（🔧 需接现有体系）
- [ ] 歌手排行 Top10 条目可点击，定位到媒体库"歌手"分类页（`CMediaClassifier` 已支持按歌手分类）。
- [ ] 点歌手后默认展示该歌手的歌曲列表。
- [ ] 无媒体库数据时给出明确提示。

**AC-6 近实时（≤1 小时）+ 标注"数据更新至 xx:xx"**（✅ 直接可实现）
- [ ] 页面角落固定显示"数据更新至 HH:MM"。
- [ ] 播放统计对话框打开期间，新产生的播放记录在 ≤1 分钟内反映（重算而非仅重读全量）；或提供手动"刷新"入口且标注更新时刻。
- [ ] 时间标注在切换时间范围/粒度时同步刷新。

**AC-7 窗口缩放自适应（AFX_DIALOG_LAYOUT）+ 图表超宽横向滚动**（原第 7 条改写，⚠️ 半适用）
- [ ] 主对话框及所有 Tab 页沿用 `AFX_DIALOG_LAYOUT` 百分比布局缩放，**不新增手动 `OnSize` MoveWindow**（避免与 CMFCDynamicLayout 冲突，参考现有实现）。
- [ ] 缩放窗口时，图表区控件跟随缩放（不遮挡、不越界），最小尺寸设下限（如主对话框 ≥520x340）。
- [ ] 当图表所需宽度超过可视区时，提供横向滚动条（或横向滚动区域），使热力图等超宽图表可完整查看。
- [ ] 图表内容随控件缩放重绘，切换 Tab / 缩放窗口不出现残影或错位。

> - **P0｜地基地**：其它功能都依赖它，必须最先做。

**REQ-001　全局时间范围与粒度过滤器（含主对话框布局改造）**
- 用户价值：一处圈定时间/粒度，全部页面统一跟着算——这是钻取、联动、报告一切功能的地基。
- 验收标准：
  - [ ] 主对话框新增控件：范围预设下拉、起日期、止日期、"天/周/月/年"按钮组、"？"说明按钮、"数据更新至"标注；可放入改造后的主对话框布局（见 §5）。
  - [ ] 维护一个全局状态结构（时间范围 + 粒度 + 过滤后的记录集），所有子页通过统一接口取数，禁止各页各自过滤。
  - [ ] 任一控件变更触发全局重算并广播到全部已加载子页。
  - [ ] 切换 Tab 不丢失当前过滤器状态。
- 依赖：现有 `CPlayStatisticsDlg`（`LoadRecords()`）、`CTabCtrlEx`、`CBaseDialog` 基类；无前置 REQ。
- 是否新增数据字段：否（状态仅驻留内存，可选持久化到配置文件记住上次选择）。

---

**REQ-002　统计聚合缓存层与增量失效（⚠️ 本版不实现，降级为 P2 可选）**
- 现状：**本版不实现聚合缓存，从 P0 移除。** 降级依据见架构文档 D2 / 附录 C。
- 降级依据（实测）：playlog 为纯文本 jsonl，2 万条规模用 CPython 做**完整 JSON 解析**仅 70.3ms、聚合 9.2ms（合计 ≈80ms）；C++ Release 手写解析为原生代码且只做定长 key 查找，预估 10~40ms，相对 NFR-1 的 1000ms 预算有 25~100 倍余量。引入缓存的收益（省几十毫秒）远小于其成本（追加写→当日缓存失效一致性、缓存损坏→全量重算降级、新增 bug 面）。**不让缓存拖累首批交付。**
- 本版替代方案：对话框打开期**内存只解析一次** playlog（`m_all_records`），后续过滤/重算都在内存完成；REQ-006 的「近实时」= 60s 定时**增量重读当月 playlog 文件 + 全量重算**（不落盘缓存）。
- 若未来数据规模突破（如 > 10 万条）确需缓存，按架构文档附录 C 单独立项，不影响本版接口。

**REQ-003　统计口径版本号（`StatSummary.schema_version`）与口径变更记录**
- 用户价值：口径调整可追溯，避免"为什么上个月数字和这个月不一样"。
- 验收标准：
  - [ ] `StatSummary` 新增 `int schema_version`；本版**定为 2**（v1＝现状；v2＝统一 15 秒口径，见 REQ-004），随每次口径调整递增并写注释/变更日志。
  - [ ] 变更记录可被"口径说明"页读取显示（如"v2：统一时段统计 15 秒口径；时段/小时分布此后与其它指标一致"）。
- 依赖：`StatAnalysis.h`（`StatSummary` 结构体）；为 REQ-004 提供内容。（原"缓存文件记录生成时的 schema_version，版本不一致时强制重算"条款**本版不适用**——REQ-002 缓存已降级，见架构文档 D2。）
- 是否新增数据字段：是。`StatSummary.schema_version`（内存结构体字段）；变更记录落盘 `config_dir/statistics/schema_changelog.txt`；无需旧数据迁移（缺失时按当前版本处理）。

## 7. 待确认问题（已于 2026-09-16 由主理人拍板，结论见各条）

**Q1　分享海报默认是否带昵称水印？**
建议：**默认无水印**，在设置中提供"分享海报加昵称"开关（与《用户故事-整理版》第六节一致）。理由：分享场景多样，默认无水印更通用，也避免隐私外泄。
**主理人拍板**：采纳——默认无水印，昵称水印为设置项（可关）。

**Q2　主对话框默认尺寸是否允许从 500x320 放大到 680x400？**
建议：**允许**，并设最小尺寸下限 `520x340`。理由：过滤条（范围+起止日期+四档粒度+？+更新至）约需 580px，500px 无法容纳；对话框本身已支持 `WS_THICKFRAME/WS_MAXIMIZEBOX` 缩放，放大默认尺寸不破坏自适应行为。
**主理人拍板**：批准 680x400，最小尺寸 520x340。

**Q3　全局时间范围的默认值？**
建议：**默认"近 30 天"**（对应 AC-1），下拉可切"全部/今年/去年/自定义"。理由：默认展示近期更有信息量，"全部"在 3 年数据下会让图表过密。
**主理人拍板**：采纳——默认"近 30 天"（与 AC-1 一致）。

**Q4　语言分布本版如何处理（无 `language` 字段）？**
建议：**本版不采用"用流派近似"**（不可靠），改为在标签编辑中补 `language` 字段采集（REQ-205），字段就绪前该页显示"待标注"。理由：与文档"建议 P2 补采集"一致，避免错误结论。
**主理人拍板**：采纳——不采用流派近似，本版补 `language` 采集（REQ-205），字段就绪前显示"待标注"。

**Q5　"五维雷达图"的"怀旧度"维度如何处理（无发行年份）？**
建议：**本版不做发行年份采集**，将雷达图维度定为"探索/专注/夜行/专一/新鲜"（去掉依赖发行年份的怀旧度），或怀旧度用"反复收听老歌占比"的简规则近似并在文案标注为近似值。理由：发行年份需补采集且可靠性存疑，优先保证零新依赖与可解释。
**主理人拍板**：维度固定为"探索/专注/夜行/专一/新鲜"；**不做怀旧度近似**（不引入无可靠数据源支撑的指标），发行年份采集本版不做。

## 附录 B：风险与依赖提示（节选）

- **R1 历史数据起始点**：playlog 自 2026-07 起积累，同比/去年对比在数据不足时必须显示"无记录"，不画假数据。
- **R2 聚合缓存一致性**：原"加缓存后须同步失效当日缓存"的风险随 REQ-002 降级消除（本版不落盘缓存）；改为"对话框打开期内存只解析一次 + 60s 定时增量重读当月文件并全量重算"，注意重读瞬间文件可能正被追加写入，需容错半行（解析失败跳过该行）。
- **R3 GDI 命中测试工作量**：钻取/联动/热力图都依赖按图表类型分别实现 `WM_MOUSEMOVE/WM_LBUTTONDOWN` 命中测试，是 P2 主要工作量来源。
- **R4 tab.dll 配对纪律**：Debug/Release STL 跨 DLL 边界不可混用；若新增 C++ 动态库须同步进 `dll/x64/{Debug,Release}` 双份。
- **R5 AI 隐私承诺**：接模型前做字段白名单过滤，"仅发送聚合统计值"，`file_path`/歌名明细不出本机（REQ-215）。
- **R6 资源编码**：`MusicPlayer2.rc` 改动必须保持 UTF-16LE-BOM；建议用支持该编码的编辑器/脚本改，避免整文件损坏。
