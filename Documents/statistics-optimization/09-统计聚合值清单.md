# 09 · 统计聚合值清单（`CStatAnalysis`）

> 用途：写「AI 设置页」「AI 对话页」之前的参考资料。
> 基线：`HEAD 402bbd0`（2026-09-19）
> 结论先行：**聚合层是纯算法、无 UI 依赖的，AI 功能直接用现成的，不用新写聚合**。

---

## 0. 一句话

`MusicPlayer2/StatAnalysis.h/.cpp` 里的 `CStatAnalysis` 一共 **14 个聚合结构**，
全部只依赖 `PlayRecord` 这一个输入类型，**没有任何 UI / MFC 依赖**（连日期减法都是自己算的）。

所以后面做 AI 功能时：**这一层一行都不用改**，要做的只是「把聚合结果拼成 prompt」。

## 2. 逐结构详解

### 2.1 `StatSummary`（最常用）

| 字段 | 含义 | 状态 |
|---|---|---|
| `schema_version` | 口径版本号，改口径时必须 +1 | 在用 |
| `total_count` | 累计播放次数（已过 15 秒口径） | ✅ |
| `total_duration_sec` | 累计播放时长（秒） | ✅ |
| `active_days` | 有播放记录的天数 | ✅ |
| `total_songs` | 听过的不同曲目数 | ✅ |
| `completed_count` / `completed_rate` | 完整听完次数 / 完播率(0~100) | ✅ |
| `skip_rate` | 跳过率(0~100) | ✅ |
| `night_owl_sec` / `night_owl_percent` | 0-6 点收听时长 / 占比 | ✅ |
| `weekend_percent` | 周末占播放次数比 | ✅ |
| `current_streak` / `longest_streak` | 当前 / 最长连续听歌天数 | ✅ |
| `repeat_depth` | 听 5 遍以上的曲目数 | ✅ |
| `explore_percent` | 探索型占比（只听 1 次的曲目占比） | ✅ |
| `new_songs_month` | 本月第一次听的曲子数 | ✅ |
| `avg_completion` | 平均完成度（时长/曲长，0~100） | ✅ |
| `top_artist` / `top_artist_sec` | 最爱歌手 / 其累计时长 | ✅ |
| `top_song` / `top_song_artist` / `top_song_count` | 最爱曲目 / 歌手 / 次数 | ✅ |
| `badges` | 徽章数组（5 种，见下） | ✅ |
| ⚠️ `today_count` / `week_count` / `month_count` | 今日 / 本周 / 本月次数 | **闲置** |
| ⚠️ `today_active_hour` | 今日最活跃小时（-1 无记录） | **闲置** |
| ⚠️ `one_hit_wonders` | 只听过 1 次的曲子数 | **闲置** |
| ⚠️ `inflation_percent` | Top10 曲目占播放次数比（集中度） | **闲置** |
| ⚠️ `avg_plays_per_day` | 日均播放次数 | **闲置** |
| ⚠️ `first_hour` / `last_hour` | 最常听歌时段的起止 | **闲置** |

**徽章（`badges`）触发规则**（`ComputeSummary` 内，需 `total_count >= 10`）：

| key | 名称 | 触发条件 | 文案 |
|---|---|---|---|
| `night` | 夜猫子 | `night_owl_sec >= 3600` | 深夜时段听了 X |
| `streak` | 连听达人 | `current_streak >= 3` | 已连续 N 天听歌 |
| `listener` | 完整聆听者 | `completed_rate >= 70` | 完整收听率 X% |
| `repeat` | 循环狂魔 | `repeat_depth >= 10` | N 首歌听了 5 遍以上 |
| `explore` | 探索先锋 | `explore_percent >= 50` | X% 的歌只听过一次 |

### 2.2 `FinishBreakdown`

`total` / `completed` / `skipped` / `stopped` / `errored` /
`avg_completion`（平均完成度）/ `avg_skip_completion`（**仅跳过记录的**平均完成度；无跳过时为 `-1`，界面显示「—」）

### 2.3 三种排行

- `ArtistRankItem`：`artist` / `duration_sec` / `count` / `song_count`
- `AlbumRankItem`：`album` / `duration_sec` / `count`
- `SongRankItem`：`file_path` / `title` / `artist` / `count` / `duration_sec` / `last_ymd`

空名字统一归入「未知歌手 / 未知专辑 / 未知标题」。

### 2.4 `PeriodBucket`（时间分桶）

`key`（天=YYYYMMDD / 周=YYYYWW / 月=YYYYMM / 年=YYYY）/ `label` / `count` / `duration_sec` / `completed_count` / `skipped_count`

### 2.5 `HeatCell`

`ymd` / `count` / `duration_sec` —— 逐日一格，本来是给 GitHub 风格热力图准备的。

### 2.6 `SkipBucket`

`index`(0~3) / `label`(如 "0~25%") / `count` / `percent`

### 2.7 `PeriodComparison`

`current` / `previous` / `last_year`（三个 `PeriodBucket`）/ `count_delta` / `count_delta_percent` /
`has_previous` / `has_last_year` / `same_as_previous`（年粒度下二者重合）

**⚠️ 数据从 2026-07 才开始积累**，`has_last_year` 基本为 false，界面要如实说「去年无记录」。

### 2.8 `RetiredGem`

`file_path` / `title` / `artist` / `count` —— 条件：`count >= 3` 且**一次都没完整听完**。

### 2.9 `PlaylistContribution`

`source` / `count` / `duration_sec` / `percent` —— 按 `playlist_source` 聚合。

### 2.10 `RadarScore`

`explore` / `focus` / `night` / `loyalty` / `fresh`（各 0~100）
——维度是用户故事里调整过的版本（去掉了没数据的「社交」）。

### 2.11 `YearReview`

`year` / `count` / `duration_sec` / `top_artist` / `top_song`

### 2.12 `InsightSongItem`（本次新加）

`file_path` / `title` / `artist` / `ymd` / `count` / `completion`
- `ComputeRecentDiscoveries(all_records, days=7)`：`ymd` = **首次播放日**
- `ComputeWorthReplaying(all_records, min_completion=80, idle_days=180, min_count=2)`：`ymd` = **最后播放日**

**⚠️ 这两个必须传「全量记录」**（`m_all_records`），传过滤后的集合测不准。

## 3. 消费方（谁在用）

目前只有**两处**：

| 消费方 | 用到的聚合 |
|---|---|
| **`CPlayLogStatDlg`**（歌曲详细记录页）<br>含列表页 + 洞察页 | 几乎全部（见下表） |
| **`CStatHtmlReport`**（网页报告） | **只调了 `ComputeBuckets`**；其余靠主对话框把算好的 `summary` 传进 `GenerateAndOpen()` |

**`CPlayLogStatDlg` 的调用分工**：

- `ApplyFilter()`（数据流水线）：`ComputeSummary` / `ComputeFinishBreakdown` /
  `ComputeArtistRank` / `ComputeAlbumRank` / `ComputeSongRank` / `ComputeBuckets` / `ComputeHourHistogram`
  —— 算完装进 `PlayLogStatData m_data`，**往下发，不重复算**
- `FillInsightView()`（洞察页）：`ComputeStreakMiss` / `ComputeSkipDistribution` / `ComputeRetiredGems` /
  `ComputePeriodComparison` / `ComputeNewSongTrend` / `ComputeRecentDiscoveries` / `ComputeWorthReplaying`

**数据源约定**：

| 用途 | 传什么 |
|---|---|
| 列表页、洞察页大部分 | `m_filtered`（跟着上方日期范围） |
| 「最近 7 天新发现」「值得重听」 | `m_all_records`（全量） |
| **AI 对话（待做）** | **`m_all_records`（全量，跟日期范围无关）** |

## 4. 闲置字段（算了但没人用）

**9 个**，全是 `StatSummary` 里的：

```
today_count  week_count  month_count  today_active_hour
one_hit_wonders  inflation_percent  avg_plays_per_day
first_hour  last_hour
```

**另外 3 个结构整体没被原生页消费**：`HeatCell`、`YearReview`、`PlaylistContribution`
（`RadarScore` 只给网页报告用，原生页没接）。

### 复用建议（给 AI 对话页）
这些闲置值不用新写聚合，直接拼进 prompt：

| 闲置字段 | 能回答什么 |
|---|---|
| `inflation_percent` | 「我听得算专一还是杂食」 |
| `one_hit_wonders` + `explore_percent` | 「我是不是喜新厌旧」 |
| `hour_hist`（在用） | 「我是早起型还是夜猫子」 |
| `HeatCell` | 「我哪天听得最多」（逐日细节） |
| `YearReview` | 「去年我都在听什么」 |

## 5. 给 AI 用的建议（进 prompt 的清单）

**「模型」档发这些**（约 600~900 token）：

```
数据范围（起止日期）
计入统计：次数 / 总时长 / 曲目数 / 活跃天数
完播率 / 跳过率 / 平均单次时长
最活跃时段 / 深夜占比 / 周末占比
连续天数（当前 / 最长）
24 小时时段分布
Top5 歌手 / 专辑 / 曲目
行为分解（播完/跳过/停止/出错）
遗珠列表
[可选] 收听集中度 inflation_percent、探索型占比 explore_percent
```

**「Max」档额外加**：一整段逐行原始记录（时间 / 标题 / 歌手 / 播放时长 / 是否完播）

**任何档位都不发**：`file_path`、歌词、封面路径

## 6. 口径提醒（写代码时容易踩）

1. **15 秒口径的唯一入口是 `CStatAnalysis::IsCounted()`**，所有聚合内部都调它，界面层不要自己判断。
2. `song_length_sec` 是**毫秒**，`play_duration_sec` 是**秒** —— 算完播率时必须 `/1000` 统一。
3. 日期解析统一走 `YmdOf()` / `HourOf()`，**不要再写第二套**。
4. 日期键是 `YYYYMMDD` 整数，比较大小即可判先后。
