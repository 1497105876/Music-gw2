## 3. 展示形式：三个方案，我推荐第一个

### 方案 A：纯列表（推荐）

**做法**：跟「概览」页一样——两列列表（洞察项 / 说明），用分组标题行分隔。

**优点**

- 零自绘、零图表，跟当前「原生页不做图，图形交给网页报告」的既定方向一致
- 主题色、字体、DPI 缩放全部自动跟随，不会有适配坑
- 实现快、风险低，当天就能看到东西

**缺点**：观感朴素，没有"报告感"

### 方案 B：列表 + 极少数小图

只给**五维雷达**和**热力条**开小灶（GDI 自绘），其余仍是文字。

- 优点：有一个视觉锚点，不那么干
- 缺点：引入自绘，主题/DPI 适配要自己扛

### 方案 C：卡片式自绘

整页自绘卡片流，最像「年度报告」。

- 优点：最好看
- 缺点：工作量大，要自己处理后画、滚动条、主题切换

**我推荐 A。** 理由：这一页的价值在**内容本身**（那些发现是否说得准、说得有意思），不在视觉。等文案定稿了、你真觉得需要，再给某几条单独配图也不迟 —— 反过来先做视觉、内容还没定，返工成本很高。

## 5. 技术实现要点（预估）

| 项    | 说明                                                        |
| ---- | --------------------------------------------------------- |
| 改动文件 | 只涉及 `PlayLogStatisticsDlg.h/.cpp`（**`StatAnalysis` 不用动**） |
| 主函数  | 新增 `FillInsightView()`，替掉现在的 `FillPlaceholderView`        |
| 列结构  | 2 列（洞察项 / 说明），跟概览页一致；分组标题行分隔                              |
| 数据装载 | 在 `ApplyFilter()` 里按需多算几个聚合（热力/环比/遗珠/雷达，都是毫秒级）            |
| 空态   | 记录数太少时（比如 < 10 条）不打徽章，改显示「数据还太少，多听几天再来看看」                 |
| 刷新   | 复用现有的 3 秒防抖 + 60 秒兜底，不用新增机制                               |

**性能**：这些聚合都是单遍扫描，1~2 万条记录在毫秒级，不影响首屏。

## 8. 我额外想加的两条（"拓展信息"）

这两条**聚合层没有现成函数**，要新写，但都不难：

1. **"本周新发现"**——从全量记录里找出**最近 7 天首次播放**的曲子，单独列一小段。  
   用户故事里 3.2 的「新发现统计」是趋势图，这里做个"最近发现了什么"的文字版更即时。  
   （实现：扫一遍全量记录，按 file_path 取首次播放日期，筛最近 7 天）
2. **"值得重听"**——挑出**完播率高、但这半年没再听过**的曲子，推荐重听。  
   这是"洞察"里少有的**能指导行动**的一条，比单纯罗列统计更有价值。  
   （实现：全量记录里按 file_path 统计完播率 + 最后播放日期，取完播率 ≥80% 且 last_ymd 早于半年前的）

**要不要加这两条，你定。** 我觉得第 2 条价值最高——它不只是回顾，而是给了一个"现在该听什么"的建议。
